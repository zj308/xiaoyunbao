# 云伴 CampusCare 云端版竞赛项目执行方案

## 0. 使用说明

本方案用于参加“2026 年 iCAN 大学生创新创业大赛 AI 应用创新挑战赛”。通知页面显示报名截止时间为 **2026 年 9 月 30 日**；初赛、决赛日期和提交文件格式以通知附件 PDF 为准。

本文档是当前执行版本，已经把原来的“电脑本地中转”改为“云端中转服务”。原固件提示词不修改，现有 ESP32-S3、麦克风、屏幕、功放、按键、ASR、TTS、逐句显示和连续聆听功能作为稳定基线保留。

## 1. 最终产品定义

### 1.1 项目名称

**云伴 CampusCare：面向大学生的多模态情绪支持与英语四级陪练终端**

### 1.2 一句话介绍

这是一个可手持的语音 AI 终端。它在用户同意后结合语音内容、语气和摄像头表情线索，提供有边界的情绪支持、具体的校园问题解决建议和英语四级听说训练；发现高风险表达时进行提醒并转介人工资源，不替代心理老师或医生。

### 1.3 必须实现的两个模式

**情绪支持模式**：共情回应、问题拆解、60 秒微行动、校园资源推荐、风险提醒与转介。

**英语四级模式**：校园场景对话、四级口语问答、听力复述、词汇复习。每轮给出发音清晰度、关键词覆盖、语法建议和下一句示范。

### 1.4 产品边界

申报书和答辩不能写“诊断抑郁症”“治愈心理问题”“替代心理老师”。统一使用“情绪状态线索、主动关怀、风险提醒、微行动建议、人工转介”。摄像头结果只能辅助对话，不能作为医学判断依据。

## 3. UI 交互定义

### 3.1 屏幕统一布局

屏幕按 240×320 设计，禁止每个页面重新定义坐标：

```text
┌────────────────────────┐ y=0
│ 模式       WiFi  摄像头 │ 0~30：顶栏
├────────────────────────┤
│                        │
│       云宝表情/状态     │ 31~160：状态区
│                        │
├────────────────────────┤ y=171
│ 用户/云宝对话文字       │ 172~315：聊天区，7行
└────────────────────────┘ y=319
```

顶栏固定显示：`情绪支持` 或 `英语四级`、Wi-Fi 状态、摄像头状态。摄像头关闭时显示“镜头关”；开启时显示绿色小圆点和“仅分析不保存”。

文字使用 16 px 粗体中文字体；若字体本身没有粗体，采用横向偏移 1 px 叠画。用户话语用高亮白色，云宝回复用黄色或青绿色，风险提醒用红色/橙色。不得用低对比度灰字。

### 3.2 页面和状态

| 状态 | 屏幕显示 | 进入条件 | 退出条件 |
|---|---|---|---|
| `BOOT` 启动 | Logo、固件版本、网络连接、摄像头隐私状态 | 上电/复位 | 初始化完成 |
| `HOME_CN` 中文首页 | “情绪支持模式”、按键唤醒、摄像头开关状态 | 启动完成或中文模式结束 | GPIO18、语音唤醒或 GPIO21 |
| `HOME_EN` 英语首页 | “CET-4 英语模式”、任务名称、今日练习次数 | GPIO21 切换 | GPIO18、GPIO21 |
| `LISTENING` 聆听 | “请说话”、波形、10 秒计时、实时识别文字 | GPIO18 唤醒 | 句末、超时、GPIO18 取消 |
| `THINKING` 思考 | 用户完整问题、云端连接、三个点动画 | ASR 提交成功 | 首句文本到达或错误 |
| `SPEAKING` 播放 | 用户话语、空一行、当前正在播放的云宝句子 | TTS 首包到达 | `audio_end` 后转首页/聆听 |
| `EN_SCORE` 英语反馈 | 发音、关键词、语法、建议分数 | 英语句子播放结束 | GPIO18 开始下一题 |
| `RISK_HELP` 风险转介 | “我可能判断错了，请联系身边的人/学校心理中心/急救资源” | 风险等级达到阈值 | 用户确认、GPIO18 重播、超时 |
| `ERROR_OFFLINE` 错误 | 网络/云端/麦克风错误及重试提示 | 连接失败或服务异常 | 自动重连成功或 GPIO18 重试 |

### 3.3 中文情绪支持流程

```text
HOME_CN
  ↓ GPIO18
LISTENING（显示实时识别，不显示旧回复）
  ↓ 句末/再次按键
THINKING（固定用户原话，显示“正在准备回复”）
  ↓ sentence_id=0 的文本和音频都准备好
SPEAKING（先显示第1句，再播放第1句）
  ↓ 下一句音频开始播放
SPEAKING（只追加下一句，上一句保留）
  ↓ audio_end
HOME_CN 或 LISTENING
```

聊天区必须按下面的顺序渲染，回复不能提前整段出现：

```text
我：最近考试压力很大。

云宝：听起来你这几天真的很累。
      我们先把今天最急的一件事列出来。
```

每句回复收到 `sentence_start` 时才写入屏幕；声音播放结束收到 `sentence_end` 后才允许进入下一句。每句最多占 2~3 行，超过聊天区时整体向上滚动一行，绝不清空上一页导致回复消失。回复结束后保留本轮最后 7 行，下一轮开始时再滚动。

### 3.4 英语四级流程

1. 在 `HOME_CN` 短按 GPIO21，切换到 `HOME_EN`；屏幕显示“已切换到英语四级模式”，停留 1.2 秒。
2. `HOME_EN` 显示任务：`1 校园对话  2 四级问答  3 听力复述  4 词汇复习`。GPIO21 短按循环任务，GPIO18 开始当前任务。
3. `LISTENING` 显示英文识别结果；不要同时显示大段中文翻译。
4. `EN_SCORE` 显示 3 项短指标：`发音清晰度`、`关键词`、`语法`，底部显示一句可模仿的正确示范。
5. 再按 GPIO18 开始下一题；长按/连续按 GPIO21 回到中文模式。

英语模式的回复要短：每次先给 1 句英文示范，再给最多 1 行中文提示，避免 TTS 过长。

### 3.5 四个按键最终定义

| 按键 | GPIO | 待机 | 聆听中 | 播放中 |
|---|---:|---|---|---|
| 唤醒/确认 | 18 | 开始聆听 | 提前提交/再次按取消 | 中断当前句并重新聆听 |
| 模式/任务 | 21 | 中文/英语切换；英语模式循环任务 | 忽略，避免误触 | 长按回首页，短按不打断 |
| 增亮 | 47 | 亮度 +10%，弹出“亮度 80%” | 亮度 +10% | 亮度 +10% |
| 减暗 | 48 | 亮度 -10%，最低 10% | 亮度 -10% | 亮度 -10% |

按键去抖 45 ms；亮度变化只刷新顶栏提示，不重绘聊天历史。摄像头开关建议使用 GPIO21 长按 1.5 秒，在首页执行，切换后显示隐私提示。

## 4. 云端服务器方案

### 4.1 架构

取消“ESP32 连接开发电脑本地 IP”的方案，改成：

```text
ESP32-S3 ──WSS/443──> 云端 API 网关
   │                       ├─ 设备认证/心跳/重连
   │                       ├─ ASR（16 kHz 单声道）
   │                       ├─ 千问流式文本（保留原提示词）
摄像头 ─WSS/HTTPS──────> ├─ 视觉推理与置信度
                           ├─ 风险规则与校园资源检索
                           ├─ 按句切分 -> TTS 短句队列
                           ├─ 音频/文字事件顺序控制
                           └─ 匿名指标与健康检查
```

推荐使用与百炼同地域的云服务器，例如阿里云 ECS Ubuntu 22.04，起步 2 vCPU/4 GB/5 Mbps；用 Docker Compose 部署 API、视觉服务和 Redis/SQLite（只存匿名指标）。正式演示使用域名和 HTTPS/WSS 443，不使用公网裸 `ws://IP:8000`。

### 4.2 云端域名和路径

建议统一为：

```text
WSS：wss://api.campuscare.example/ws/xiyunbao/v1
健康检查：https://api.campuscare.example/api/health
指标页面：https://api.campuscare.example/admin/metrics
```

域名只是示例，实际域名由负责云端的成员申请。ESP32 只保存域名、设备 ID 和设备令牌，不保存阿里云 API Key。百炼 Key、Workspace ID 和视觉模型 Key 只放云服务器环境变量或密钥服务中。

### 4.3 消息协议

所有消息必须带 `session_id`、`sentence_id` 和 `seq`，防止断线后旧文字或旧音频插入新会话。

| 方向 | 类型 | 必填字段 | 作用 |
|---|---|---|---|
| ESP32→云 | `hello` | `device_id`,`firmware`,`mode` | 认证和能力声明 |
| ESP32→云 | `listen.start` | `session_id`,`mode` | 开始一轮识别 |
| ESP32→云 | 二进制音频 | `session_id`,`seq` | 16 kHz/16 bit/mono 麦克风帧 |
| ESP32→云 | `listen.stop` | `session_id` | 句末或按键提交 |
| ESP32→云 | `camera.frame` | `session_id`,`seq`,`consent` | 用户同意时上传 320×240 JPEG，2~5 fps |
| 云→ESP32 | `asr.partial` | `session_id`,`text`,`seq` | 实时识别预览 |
| 云→ESP32 | `reply.sentence_start` | `session_id`,`sentence_id`,`text`,`emotion_hint`,`risk_level` | 允许屏幕显示一句 |
| 云→ESP32 | 二进制 PCM | `session_id`,`sentence_id`,`seq` | 24 kHz/16 bit/mono TTS 音频 |
| 云→ESP32 | `reply.sentence_end` | `session_id`,`sentence_id` | 当前句播放完毕 |
| 云→ESP32 | `reply.audio_end` | `session_id`,`seq` | 整条回复播放完成，立即进入聆听 |
| 云→ESP32 | `error` | `code`,`retry_after_ms` | 可恢复错误或用户提示 |

情绪字段使用 `neutral/happy/shy/sad/stressed/unknown`；视觉服务只返回粗粒度状态和置信度。风险字段使用 `none/observe/assist/emergency`，`emergency` 必须进入转介界面，不能继续普通闲聊。

### 4.4 断线和低延迟策略

- WebSocket 心跳：每 15 秒 ping，8 秒无 pong 视为断线。
- 重连间隔：2、4、8、16、30 秒指数退避，成功后恢复 2 秒。
- 音频采用生产者/消费者队列；首句缓冲目标 600~1000 ms，后续保持 1~2 秒储备，禁止每句重新鉴权。
- 千问流式文本按句切分；完整句子一到就提交 TTS，不等待整段回答。
- 视觉只在 `LISTENING` 或用户主动开启时工作，2~5 fps；非必要不上传图片。
- 云端音频发送和文字事件使用同一 `sentence_id`；ESP32 收到旧序号直接丢弃。
- API、ASR 或 TTS 暂时失败时，云端发送短句错误提示和 `retry_after_ms`；ESP32 自动回到聆听，不停在黑屏或死循环。

### 4.5 安全和隐私

1. 使用 WSS/TLS 1.2 以上；设备令牌按设备分配，可单独吊销。
2. 摄像头默认关闭，有物理遮挡或明确指示灯；上传前发送 `consent=true`。
3. 云端图像只放内存，推理后立即释放；默认不保存原图、原始音频和人脸特征。
4. 只保存匿名的延迟、成功/失败、任务得分和版本号；敏感文本不进入演示指标页面。
5. API Key 不进固件、Git、项目书截图或演示视频；使用 `.env`、云密钥服务和最小权限账号。
6. 管理后台不对公网开放，或增加 VPN/二次认证；只开放 443，SSH 限制到固定管理地址。

## 5. 四名队员的详细作业和验收

### 成员 1：项目负责人、ESP32 与云端集成

**第一阶段交付（9/4~9/7）**

- 固定现有 v77 固件为 `demo-baseline`，导出一次可烧录固件和配置模板。
- 画出状态机，定义 `hello/listen/reply/audio_end/error` 消息协议。
- 把云端地址、端口、路径、设备 ID、令牌从 `secrets.local.h` 分离；不把 Key 编译进固件。

**第二阶段交付（9/8~9/14）**

- 把当前本地 relay 地址改为域名 WSS；实现 TLS、心跳、指数退避和旧序号丢弃。
- 保证屏幕显示只由 `sentence_start` 触发，音频只播放匹配的 `sentence_id`。
- 记录首声延迟、队列最低包数、欠载次数、重连时间。

**第三阶段交付（9/15~9/20）**

- 增加 `mode=emotion/en_cet4`；GPIO21 切换模式和英语任务。
- 增加摄像头开关状态、风险等级和云端错误处理。
- 与 UI 成员联调 8 个状态：首页、聆听、思考、播放、英语反馈、风险、错误、断线。

**最终验收**

- 100 次唤醒测试成功率不少于 95%。
- 20 条长回复中欠载不超过 1 次；云端断线 10 秒内自动恢复。
- 20 条回复文字和音频 `sentence_id` 全部一致。
- 播放结束 1 秒内重新进入聆听状态。
- 交付：固件、云端 Docker 配置、API 文档、测试日志、现场备用固件。

### 成员 2：视觉算法和摄像头

**第一阶段交付（9/4~9/7）**

- 选定摄像头模块，确认供电、分辨率、视场角、接口和外壳安装位置。

**第二阶段交付（9/8~9/14）**

- 完成人脸检测和 4 类粗粒度表情线索：平静、愉快、紧张、低落/疲惫；无法判断返回 `unknown`。
- 输出固定 JSON：`face_present`、`expression_hint`、`confidence`、`timestamp`。
- 用 20~30 段自愿、脱敏样本做混淆矩阵，记录光照、角度、口罩等失败条件。

**第三阶段交付（9/15~9/20）**

- 将视觉结果作为辅助特征，不单独触发高风险结论。
- 提供“镜头关闭/无脸/低置信度”降级路径；拔掉摄像头后语音对话仍能完成。
- 完成隐私指示页和图像自动删除测试。

**最终验收**

- 正常光照下人脸检测稳定，unknown 时不误导用户。
- 摄像头断开、网络抖动、多人进入画面时服务不崩溃。

## 6. 创新点设计

### 创新点 1：会自我纠错的“情绪镜子”

屏幕不直接说“你抑郁了”，而是显示“我从语气和文字中感觉到你可能有些紧张，判断可能不准”。然后询问“你觉得这个判断接近吗？”。用户可以选择“接近/不对”，这既降低误判伤害，也可以形成个性化偏好。

### 创新点 2：情绪支持和四级学习联动

同一用户在压力大时，英语任务自动变成短句、慢语速和低难度；状态稳定时增加追问和词汇难度。这样不是“情绪机器人 + 英语机器人”两个拼盘，而是同一套自适应交互引擎。

### 创新点 3：从安慰到可执行的微行动

每次情绪支持最多给一个 60 秒行动：呼吸、喝水、拆分任务、联系同学、预约校园心理中心。下一次对话先询问是否完成，再决定继续聊天还是调整方案，体现真正的帮助闭环。

### 创新点 4：校园资源可信回答

把学校心理中心、辅导员值班、图书馆、四六级服务等公开信息做成可更新知识库。涉及校内流程时优先检索资料并显示来源日期，减少 AI 编造电话和地址。

### 创新点 5：可证明的同步和稳定性

在演示界面短暂显示 `句子 2/5`，让评委看到文字和音频共享同一序号；后台展示首声延迟、重连时间、欠载次数，而不是只说“支持流式”。

### 创新点 6：隐私优先的摄像头

摄像头有物理遮挡/指示灯、默认关闭、只传低帧率临时图像、推理后立即删除。用户可以在屏幕上看到“镜头关/镜头开”，把隐私设计变成可演示功能。

### 创新点 7：弱网可用

云端连接失败时，设备仍显示基础页面，保留本地安抚短句、英语练习卡和重新连接按钮；网络恢复后自动回到云端对话，不让整台设备变成“无网即失效”。

## 7. 评委现场演示脚本

总时长控制在 4 分钟：

1. 20 秒：介绍痛点和两个模式，展示小巧可手持样机。
2. 70 秒：中文模式说“最近考试压力很大”，展示摄像头同意、实时识别、逐句文字和同步语音。
3. 30 秒：展示“情绪镜子”自我纠错和一个 60 秒微行动。
4. 70 秒：按 GPIO21 切换英语模式，完成校园口语题，展示发音/关键词/语法反馈。
5. 30 秒：模拟网络短断，展示自动重连和不重复播放旧句。
6. 40 秒：展示风险转介页面、隐私策略、测试数据和校园推广方式。
7. 20 秒：说明成本、模块化维护和四人分工。

不要在现场依赖实时修改代码、临时联网下载模型或单块设备。准备两块已烧录样机、一个手机热点、离线音频演示和完整云端备份。

## 8. 验收指标

| 指标 | 目标 |
|---|---:|
| 中文 ASR 安静环境可理解率 | ≥90% |
| 云端首句开始播放 | 常规网络 ≤3 秒 |
| 20 条长回复音频欠载 | ≤1 次，并可自动恢复 |
| 文字/音频句子序号一致 | 20/20 |
| 云端断线自动恢复 | ≤10 秒 |
| 连续运行 | ≥2 小时无崩溃 |
| 摄像头断开降级 | 语音和英语仍可使用 |
| 高风险测试语句 | 全部进入转介流程 |
| 英语任务 | ≥4 类，有前后分数记录 |
| 用户测试 | ≥10 名自愿大学生，匿名记录 |

所有指标必须保存原始测试日期、固件版本、网络条件和测试次数。达不到的指标如实写限制，不能用估算值冒充结果。

## 9. 每周协作机制

- 每天 15 分钟站会：昨天完成、今天任务、阻塞问题。
- 每周一次集成日：四人只使用同一版本硬件、固件和云端，现场跑完整流程。
- 所有接口变更先更新本文档和消息协议，再改代码；禁止口头改字段。
- 每项任务写清“负责人、备份人、验收数据、截止时间”。
- 代码版本分为 `demo-baseline`、`cloud-mvp`、`competition-rc`；现场只使用 `competition-rc`。
